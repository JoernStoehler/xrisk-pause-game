# Presentation strategy

## Why one giant graph is the wrong default

The full subject combines technical capability, cognitive reinvestment,
alignment research, compute control, verification, organizations, domestic
politics, diplomacy, economics, war, and player knowledge. A single directed
acyclic graph would either omit feedback and time, or become unreadable.

Use a small portfolio of views:

- **module map:** fewer than roughly fifteen boxes, for orientation;
- **mechanism diagrams:** sparse local causal graphs for one intervention or
  failure process;
- **timelines/state machines:** implementation, escalation, withdrawal, and
  staged build processes;
- **influence diagrams:** decisions, observations, latent conditions, and
  outcomes for a particular choice;
- **tables:** hypothesis families, provenance, disagreements, policy variants,
  and pruning decisions;
- **equations or dense submodels:** capability measurement, resource production,
  and other relationships for which a graph adds little;
- **paired trajectories:** expert review of structural differences that are hard
  to elicit as isolated parameters.

The graph is an index into prose, equations, evidence, and disagreement records.
It is not required to contain the entire model.

## Expert-model atlas

Optimize for truthful knowledge transfer:

- state conclusions in ordinary language;
- distinguish observations, arguments, forecasts, assumptions, and values;
- preserve model plurality and weak correlations;
- make conditional forecasts explicit without completing an artificial joint
  distribution;
- cite the strongest available evidence and prominent counterarguments;
- mark where Jörn's model, Yudkowsky/MIRI, other experts, and project inference
  differ;
- leave unused detail informal when formalization has low decision value.

The atlas should answer “what do you believe and why?” It need not be executable.

## Symbolic game model

Optimize for completeness and auditability of the approximation:

- every canonical state object is typed;
- every effect has an explicit transition and implementation path;
- observations are distinct from latent truth;
- stochasticity identifies its persistent sampled hypothesis and named shock;
- policy actions cannot grant authority or successful implementation by fiat;
- terminal outcomes arise through causal processes;
- every omitted or compressed expert mechanism has a recorded disposition;
- the document can be compared mechanically or manually with code.

The symbolic model should answer “what exactly does the game assume and do?”

## Review interface

Optimize for fast disagreement:

- show one review object at a time;
- ask for missing/reversed edges before probabilities;
- ask conditional or comparative questions when absolute numbers are unstable;
- provide a “roughly right / incoherent / reversed / missing mechanism” response
  grammar;
- separate structural disagreement, parameter disagreement, evidence dispute,
  abstraction harm, and writing ambiguity;
- display the downstream code/content decisions affected by the answer;
- batch only high-consequence questions that ordinary research did not settle.

## Crosswalk

For each game mechanism, maintain:

1. expert-model claim(s) it approximates;
2. game object and transition;
3. preserved policy ordering or public lesson;
4. information deliberately discarded;
5. failure conditions for the abstraction;
6. review status and owner;
7. player-facing manifestations and postmortem explanation.

The crosswalk is not an attempt to formalize the entire expert model. It is a
test that simplification is harmless for the decisions the game actually asks.
