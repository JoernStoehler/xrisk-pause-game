# One expert crux in three simple event grammars

Status: **concrete design scripts for comparison; all player-facing words are
unapproved draft playability transforms**. Site names, characters, timings, and
outcomes below are diagnostic fiction, not predictions. Relative branch
frequencies are intentionally unspecified.

## The shared crux

All three versions teach the same expert-model distinction:

> A legal prohibition and credible punishment can deter many ordinary actors,
> but they do not themselves remove the factual ability to start a dangerous
> workload. Joint custody or another direct interruption layer covers a
> different residual class. Authority, implementation, control, conduct,
> evidence, and the Director's knowledge remain separate.

Claim status: the deterrence/direct-control complement is a dated Jörn judgment
recorded in a polished paraphrase, then integrated into the project synthesis.
The US/PRC founding context is a scenario premise. The particular site, people,
startup test, bypass, and timing in these scripts are draft diagnostic fixtures.

Each grammar uses the same small latent case:

```yaml
case_id: JOINT-KEY-01
site: declared frontier site Orion-4
known_at_start:
  legal_halt: in_force
  operator_acknowledgment: received
  current_credential_holder: operator
  proposed_control: ISIA-host-state two-person authorization
hidden_in_sampled_world:
  ordinary_team_would_obey_order: true
  residual_insider_attempt_if_unilateral_path_remains: true
  insider_can_start_with_operator-only_credentials: true
  insider_cannot_start_with_split_credentials: true
  telemetry_and_reporting: imperfect
not_claimed:
  frequency_of_this_world
  universal_sufficiency_of_split_credentials
  exact_real_site_or_law
```

Matched comparison:

- **Order only:** the ordinary team stands down; a residual insider later has a
  technical startup path.
- **Split credentials:** the ordinary team still stands down; the same residual
  attempt fails closed before a workload starts.

The direct-control choice is better in this diagnostic case, but the text must
name residual risks: credential theft, collusion, power/network/weight access,
restart procedures, covert resources, and domestic implementation failure.
The lesson is complementarity, not "two keys solve AI governance."

## Grammar A: advisor browse, then confirm

### Interaction contract

One mobile screen shows the case statement, three advisor tabs, and a persistent
`ISSUE ORDER` button. The player may open advisors in any order. Opening all
three is useful but not mandatory. Confirming shows the selected order, named
implementer, expected first receipt, and known residual path.

This grammar emphasizes people, partial views, and executive judgment.

### Beat-by-beat script

All quoted text in this section is **DRAFT / UNAPPROVED**.

1. **Case arrives — 08:10**

   Commissioner for Site Control:

   > "Orion-4 acknowledged the halt. Its operator still holds every launch
   > credential."

   Case header: `DECLARED SITE · HALT ACKNOWLEDGED · STARTUP PATH UNTESTED`

2. **Browse: legal counsel**

   > "The order is in force. A knowing violation can be prosecuted. That can
   > stop people who expect to live with the consequences."

   Evidence chip: `LEGAL AUTHORITY — CONFIRMED`

   Rival/limit chip: `DOES NOT CHANGE CREDENTIALS`

3. **Browse: site-control commissioner**

   > "We can split authorization between the host state and ISIA by tonight.
   > The operator will lose the unilateral startup path."

   Evidence chip: `VOLUNTARY IMPLEMENTATION WINDOW — 9 HOURS`

   Rival/limit chip: `COLLUSION AND OTHER ACCESS PATHS REMAIN`

4. **Browse: political liaison**

   > "The operator says a second key implies we expect treason. They will accept
   > it now, but want a review date and a restart procedure for permitted work."

   Evidence chip: `OPERATOR ACCEPTANCE — CONDITIONAL`

   Rival/limit chip: `FUTURE BARGAINING COST`

5. **Select order**

   - `ENFORCE THE HALT ORDER`
     - foreseeable effect: `Keeps operator control; criminal deterrence remains.`
   - `SPLIT STARTUP AUTHORIZATION`
     - foreseeable effect: `Adds a factual startup barrier; requires an
       implemented custody protocol.`

6. **Confirm sheet**

   Example for split authorization:

   > "You are ordering the host authority and ISIA site team to require both
   > credentials before a prohibited accelerator pool can start. First receipt:
   > key ceremony and cold-start test by 18:00."

   Buttons: `BACK` / `ISSUE ORDER`

7. **Implementation receipts**

   - 12:40 `HOST AUTHORITY ACCEPTED`
   - 16:05 `OPERATOR PROCEDURE NARROWED: emergency cooling remains unilateral`
   - 18:22 `TWO-PERSON STARTUP TEST FAILED CLOSED`

   These are known implementation facts. They are not a declaration that every
   path or actor complies.

8. **Delayed callback — six weeks later**

   > "An engineer presented a valid operator credential during an unauthorized
   > overnight startup attempt. The ISIA half was absent. No workload began."

   DG-visible status: `ATTEMPT REPORTED · STARTUP BLOCKED`

9. **Retrospective (separate surface)**

   > "In this sampled world, the ordinary training team would have obeyed the
   > legal order under either policy. A different insider was willing to gamble.
   > Split authorization blocked that person's available path. It did not prove
   > the site universally secure."

   Same-world comparison highlights the first divergence:
   `02:13 — operator credential accepted` versus
   `02:13 — second authorization missing; startup aborted`.

### State/trace mapping

| Beat | Intended model boundary |
| --- | --- |
| legal counsel | legal threshold and sanction expectation |
| site-control advice | factual credential control and implementation latency |
| political liaison | adaptation, legitimacy, due process/reversibility |
| confirm sheet | DG choice versus domestic/operational implementation |
| receipts | authority and implementation result, not hidden compliance |
| delayed attempt | actor conduct meets factual control |
| retrospective | selected latent cause and paired counterfactual |

### Strengths and failure modes

- Strongest pleasure: advisor relationship and informed executive choice.
- Strongest teaching feature: three professional views describe different
  causal layers without a lecture.
- Mobile cost: three short optional tabs plus one confirm sheet.
- Distortion risk: players may infer one advisor is always correct. Later cases
  must show each office's blind spots and incentives without manufacturing fake
  neutrality.
- Replay variation: change implementation narrowing, credential bypass,
  reporting delivery, or whether the residual actor exists while preserving
  persistent world hypotheses.

## Grammar B: control-path assembly and live test

### Interaction contract

The player sees one compact vertical path, not advisors:

```text
LEGAL HALT       ✓
START AUTHORITY  [ OPERATOR ]
POWER CUTOFF     [ HOST ]
LOCAL MONITOR    [ INSTALLING ]
```

The task is to choose one of two operating packages and then press `TEST
CONTROL`. The test is an in-world cold-start drill, not an omniscient simulator.
This grammar is substantially different: the pleasure comes from configuring
and proving a control path rather than browsing opinions.

### Beat-by-beat script

All quoted text is **DRAFT / UNAPPROVED**.

1. **Operations brief — 08:10**

   > "Orion-4 is legally halted. Show who can still make the accelerators run."

2. **Inspect the path**

   Tapping each row reveals one sentence:

   - `LEGAL HALT`: "Violation is punishable; the order changes incentives."
   - `START AUTHORITY`: "One operator credential currently authorizes startup."
   - `POWER CUTOFF`: "The host utility can cut power after an authenticated
     request; expected delay is hours."
   - `LOCAL MONITOR`: "Installation has begun; no local stop authority yet."

3. **Choose package**

   - `ORDER + REMOTE RESPONSE`
     - diagram stays `OPERATOR → START`; ISIA response appears after the site.
   - `ORDER + SPLIT START AUTHORITY`
     - drag/tap `ISIA KEY` beside `HOST KEY`; diagram becomes
       `HOST ∧ ISIA → START`.

   Dragging always has a tap alternative. There is no free-form wiring.

4. **Commit**

   > "Authorize this control package for the Orion-4 cold-start test?"

5. **Live test**

   A three-step animation uses text and icons:

   ```text
   operator requests startup      ✓
   operator credential validates  ✓
   second authorization missing   BLOCKED
   ```

   Under order-only, the drill reaches `ACCELERATOR POOL ENERGIZED`, followed by
   `REMOTE STOP REQUESTED · ESTIMATED 3H 40M`. The drill is then safely ended by
   the operator; it does not imply a real dangerous run was permitted.

6. **Receipt**

   > "Control test complete. The law was identical in both packages. Startup
   > authority was not."

7. **Delayed incident**

   The same overnight attempt from Grammar A tests the installed path. The
   player sees the relevant three rows light in sequence, then the factual
   outcome.

8. **After-action comparison**

   The game overlays the two matched traces and circles the first divergence,
   without displaying a probability of catastrophe.

### State/trace mapping

| UI row | Model field/interface |
| --- | --- |
| Legal halt | `control_regime.legal_thresholds` and deterrence |
| Start authority | credential/workload access graph |
| Power cutoff | separate physical interruption path and latency |
| Local monitor | telemetry, stop authority, and installation state |
| Live test | known implementation receipt, not true future compliance |

### Strengths and failure modes

- Strongest pleasure: visible world change and mastery; the player can point to
  what their order physically changed.
- Strongest teaching feature: law and factual control occupy separate rows.
- Mobile cost: four rows, one binary package choice, one test button.
- Distortion risk: a neat path diagram can suggest completeness. The surface
  must show `OTHER PATHS NOT ESTABLISHED` and later introduce one named bypass
  rather than filling a generic vulnerability meter.
- Replay variation: the cold-start test remains stable; later cases vary whether
  a bypass, collusion, alternative power path, or reporting failure matters.

## Grammar C: incident reconstruction with an intervention fork

### Interaction contract

The chapter opens after an anomalous startup signal. The player reconstructs
what happened by placing three timestamped facts on a tiny timeline, then chooses
where to intervene before the next attempt. This is a mystery/judgment grammar,
not a policy-menu or control-assembly interaction.

### Beat-by-beat script

All quoted text is **DRAFT / UNAPPROVED**.

1. **Alert — 02:18**

   > "Orion-4 telemetry shows a seven-second startup handshake. The operator
   > reports a maintenance test. No workload is established."

2. **Place three facts**

   The player taps the next slot for each item; wrong chronological placements
   are gently corrected because chronology is not the puzzle.

   - 02:13 `OPERATOR CREDENTIAL ACCEPTED`
   - 02:14 `ACCELERATOR CONTROL PLANE OPENED`
   - 02:18 `TELEMETRY REPORT REACHED INSPECTORATE`

3. **Mark what each fact establishes**

   For each item choose one of two labels:

   - `CONTROL CHANGED` / `EVIDENCE PRODUCED`
   - `WORKLOAD PROVEN` / `WORKLOAD NOT YET PROVEN`

   Feedback is immediate and explanatory; it is not scored.

4. **Intervention fork before the next shift**

   - `INVESTIGATE THE REPORTED PURPOSE`
     - adds evidence; operator retains the unilateral startup path meanwhile.
   - `SPLIT START AUTHORITY, THEN INVESTIGATE`
     - changes feasibility first; investigation and due process remain open.

5. **Named domestic receipt**

   The host authority can accept, narrow, delay, or block the request for a
   stated reason. For this diagnostic script it accepts and implements the split
   at 18:22.

6. **Second attempt**

   The same residual insider returns. The timeline branches:

   - order-only: credential accepted → startup begins → report/response race;
   - split: credential accepted → second key absent → no startup.

7. **Debrief question**

   > "Which statement is justified?"

   - `The first alert proved a prohibited workload.`
   - `The first alert exposed a unilateral startup path.`

   The second is correct in this authored case. It does not assert the reported
   purpose was false.

8. **Retrospective reveal**

   Only after the chapter, clearly outside DG knowledge, disclose that the
   sampled residual actor intended a prohibited run. Explain that the player's
   intervention was justified by the exposed control path even before that
   intent was known.

### State/trace mapping

| Beat | Intended boundary |
| --- | --- |
| anomaly | sensor output distinct from conduct |
| operator report | declaration distinct from truth |
| timestamp reconstruction | control event distinct from later report receipt |
| intervention | evidence-seeking versus feasibility-changing action |
| domestic receipt | DG choice distinct from implementation |
| retrospective | latent intent revealed only after play |

### Strengths and failure modes

- Strongest pleasure: fair mystery and crisis judgment.
- Strongest teaching feature: a player can act robustly without pretending to
  know whether the first event was cheating.
- Mobile cost: three timeline items, two binary classifications, one order.
- Distortion risk: detective stories imply one hidden truth is always available
  at the end. Some later cases should retain two live explanations after the
  retrospective and compare actions robust to both.
- Replay variation: telemetry can be true, false, or filtered; intent and
  workload can differ; the control-path lesson persists only when the matched
  setup makes it relevant.

## Comparison and recommendation

| Criterion | A: advisor browse | B: control-path test | C: incident reconstruction |
| --- | --- | --- | --- |
| Immediate character appeal | Strong | Weak | Medium |
| Direct-power fantasy | Medium | Strong | Strong |
| Visible world change | Medium | Strong | Medium |
| Teaches authority/control separation | Strong | Very strong | Strong |
| Teaches evidence/truth separation | Medium | Weak | Very strong |
| One-hand mobile simplicity | Strong | Medium–strong | Medium |
| Replay legibility | Strong | Very strong | Strong |
| Main distortion to guard | advisor as truth oracle | diagram as complete security | mystery as uniquely solvable truth |

Prototype **A and B first as the same chapter**: A supplies the recurring human
rhythm; B can be the 20–30 second implementation/test beat after confirmation.
Use C as the delayed callback or as a second prototype if the combined version
feels too predetermined. This tests whether concrete operations add pleasure
and transfer without replacing the mobile advisor shell.

## What must remain invariant in any implementation

- The legal halt cannot directly set the actual workload to zero.
- The DG choice cannot directly set domestic implementation to success.
- The ordinary deterred actor and the residual actor must be distinct conduct
  branches, not one scalar compliance roll.
- Split credentials change one access path; they do not set a universal
  `secure` flag.
- Telemetry, analysis, report delivery, and DG knowledge remain separate.
- A started run is nonterminal; interruption and hidden technical progress race
  in time.
- Same-world comparison preserves unrelated draws and identifies the first
  causal divergence.
- Retrospective disclosure is visibly separate from the Director's in-world
  information.
- Every numeric time, branch, and outcome used for this case is labeled
  diagnostic fixture or playability transform unless separately calibrated.

## Jörn-review cruxes specific to this script

1. Is joint credential custody the best simple example of direct factual
   control, or should the opening crux use local power cutoff, model-weight
   custody, component removal, or another mechanism?
2. Does the order-only versus split-authorization comparison overstate how
   cleanly direct control separates from deterrence in a real site procedure?
3. Which residual risks must be named immediately so the example does not imply
   sufficiency, and which can wait for later chapters?
4. May the Director order split authorization directly in the public-game
   approximation, with domestic acceptance shown as a receipt, or must the first
   choice be a request to national authorities?
5. Is it acceptable to reveal latent insider intent in the retrospective, or
   would preserving uncertainty teach a better model?
6. Is the phrase "people who expect to live with the consequences" a faithful
   playability transform of the deterrence judgment, or rhetorically too loaded?
7. Should the matched world include an actual dangerous run on the order-only
   branch, or is a safe cold-start drill plus later blocked attempt sufficient
   for the first public case?
