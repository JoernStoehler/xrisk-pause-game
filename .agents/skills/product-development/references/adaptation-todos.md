# Product-Development Adaptation TODOs

Status: provisional port notes for later harness review. These are not ordinary
product-task requirements and do not authorize work by themselves.

The first port deliberately leaves these questions open until real game tasks
provide evidence:

- Does one end-to-end product-slice owner outperform separate design and
  implementation owners for the compact-loop experiment?
- Which preparation artifacts actually reduce rediscovery without becoming a
  second, stale product narrative?
- When do independent concept agents add useful alternatives, and when do they
  produce idea volume that the integration owner cannot economically compare?
- Which review lanes are missed in ordinary UI, content, model, and playtest
  work because `docs/review/REVIEW_ROUTING.md` is not discovered?
- What minimum evidence makes an artifact ready for a real target-player or
  facilitator test?
- Which parts of recurring playtest preparation and analysis should become a
  skill, schema, script, or test after a real trial?
- Would a deterministic checker for repo-relative links and skill references
  catch enough drift to justify integration into `npm run check`?
- Do product macroeconomics or sociological questions recur in a form that
  warrants a dedicated workflow, or are existing expert-model owners plus
  task-local research sufficient?

Resolve a TODO only from a live decision, observed failure, or repeated burden.
Delete questions that no longer affect project work rather than turning this
file into a permanent backlog.
