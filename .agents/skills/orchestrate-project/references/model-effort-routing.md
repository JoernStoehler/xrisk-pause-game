# Model and effort routing

Status: revisable workflow guidance, October 2026. Earlier July model-family
rankings were session observations, not benchmarks; they are recoverable in Git
at `2552820:.agents/skills/orchestrate-project/references/model-effort-routing.md`.
Model availability, versions, cost, and observed performance vary by environment.

Choose the least expensive available model and effort likely to return a
trustworthy artifact. Higher effort does not repair missing sources, ambiguous
ownership, or a bad success criterion. The coordinator still owns integration.

1. Name the decision, bounded artifact, cost of error, and validation method.
2. Use available capabilities and evidence from closely matching work. Broad
   retrieval and mechanical audits can often use a fast model; difficult
   interpretation may justify a stronger specialist. Neither family label
   establishes source quality or review authority.
3. Give sources, conditions, write boundaries, and a compact return contract.
   Ask for evidence, uncertainties, and live alternatives when relevant.
4. Escalate for an identified crux or observed failure, rather than spare budget.
   Fix task framing or missing context before paying for deeper reasoning.
5. Parallelize separable work or deliberate independent review. Account for
   duplicated context, integration cost, and overlapping edits.
6. Review the actual artifact. A source collector cannot establish human fun,
   learning, or demand by collecting more links.

When a result changes future routing, record the date, actual model/version and
effort, task and inputs, verdict scope, failure conditions, and proposed change.
Keep counterevidence. One bad prompt or one good output does not justify a
permanent capability ranking. The root needs enough capability to choose targets
and integrate evidence; it need not personally retrieve every source or perform
every hard derivation.
